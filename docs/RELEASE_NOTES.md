# Release history through 0.1.6

[Back to README](../README.md) · [GitHub releases](https://github.com/yasakani-dev/yasakani/releases)

The cumulative release notes previously at the top of the README, with the original changes and contributor references preserved.

**Version 0.1.6 (November 18, 2026).** New in this version: `yasakani bench --edit` runs the three edit tasks of the speed tables on your PC with one command and prints the speed, the tokens per pass and whether each answer is the expected one (see [Speed](../README.md#speed)); and a fix for PCs with several GPUs ([#20](https://github.com/yasakani-dev/yasakani/issues/20)). With 0.1.5, `--device 1` on a PC with two GPUs could stop with `graph instantiate failed` while the other GPU was visible. The engine now selects its GPU on every call, not only on the thread that opened it, and `chat`, `serve`, `bench` and `selfcheck` let the engine see only the GPU of `--device` (unless nvidia-smi gives no UUID for it; see [What you need](../README.md#what-you-need)). With one GPU the generated text (greedy) and the speed are those of 0.1.5 (checked on the RTX 5090); it has not yet been tried on a PC with two GPUs.

**Version 0.1.5 (November 16, 2026).** New in this version: fixes, most of them contributed. Tool calls with `<function=...>` inside a JSON argument are read correctly, the same image twice in one request is encoded once, and `--dll` or `YASAKANI_DLL` naming a file that is not there stops with an error instead of loading another library ([#12](https://github.com/yasakani-dev/yasakani/pull/12)). A tool-call argument declared as a boolean also takes Python's `True` / `False`, and one that may be null `None` ([#21](https://github.com/yasakani-dev/yasakani/pull/21)). The engine reads the header length of a model file as 64 bits ([#14](https://github.com/yasakani-dev/yasakani/pull/14)), attends to the whole of a short context also when `YSKN_Q35_ATX_SPLITS` is set below 31 (the default, 42, was not affected; [#15](https://github.com/yasakani-dev/yasakani/pull/15)), and keeps the look-ahead state of two engines in one process apart ([#13](https://github.com/yasakani-dev/yasakani/pull/13)). Its GPU code is that of 0.1.4, so the speed tables stand. `--max-ctx` leaves out the output head of the draft model when it does not fit beside the given length ([#17](https://github.com/yasakani-dev/yasakani/pull/17)). On a PC with several GPUs, `--device N` is now GPU N of `yasakani info` and nvidia-smi ([#20](https://github.com/yasakani-dev/yasakani/issues/20)). The FAQ says that a monitor on the same GPU can slow generation ([#18](https://github.com/yasakani-dev/yasakani/issues/18)). 0.1.4 brought faster edits, and less reading of long prompts again. Where the answer copies the input, one pass checks up to 64 copied tokens instead of 16: with thinking off, code and JSONL edits are 1.67 to 2.04 times as fast as with 0.1.2, the other tasks run at 0.96 to 1.01 times (as fast as 0.1.3 measured in the same sitting: 0.99 to 1.00 times), and the answers are the same (see [Speed](../README.md#speed)). The quickstart now checks the NVIDIA driver before it downloads anything, and `yasakani selfcheck` also checks GPUs other than the RTX 5090 (see [What you need](../README.md#what-you-need)). The same long document followed by a different question is no longer read again from the start (when the document comes before the question and no other request comes in between): after a 229,376-token document the first token comes after 0.37 s instead of 116 s (see [Long contexts](../README.md#long-contexts)). The server now also accepts `tool_choice` `required` and a named function (not enforced) and reports llama.cpp-style `timings`, and image input also works on Linux with llama.cpp built from source (all three contributed in [#8](https://github.com/yasakani-dev/yasakani/pull/8); image input on Linux not tried by us); [BUILDING.md](../BUILDING.md#linux-building-from-source) has a Linux section ([#10](https://github.com/yasakani-dev/yasakani/pull/10), [#8](https://github.com/yasakani-dev/yasakani/pull/8)). Since 0.1.3 the engine is also built to run on other NVIDIA RTX 30, 40 and 50 series cards with 16 GB or more; we have not run it on them, and it is not optimized for them (see [What you need](../README.md#what-you-need)). 0.1.3 also fixed the cause of a rare change of the text part-way through a run (see [Quality](../README.md#quality)). Since 0.1.2 the server can take images, optionally (contributed in [#4](https://github.com/yasakani-dev/yasakani/pull/4)). Since 0.1.1 it accepts requests with `tools` (tool / function calling), so coding agents and other tool-using apps can connect to it. Engine: [release page](https://github.com/yasakani-dev/yasakani/releases/tag/v0.1.5). Models on Hugging Face: [quality model](https://huggingface.co/yasakani-dev/Qwen3.8-27B-YASAKANI-quality) and [fastest model](https://huggingface.co/yasakani-dev/Qwen3.8-27B-YASAKANI-speed).
