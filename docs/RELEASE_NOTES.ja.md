# 公開版の更新記録（0.1.6 まで）

[README に戻る](../README.ja.md) · [GitHub のリリース](https://github.com/yasakani-dev/yasakani/releases)

README の冒頭にあった更新記録をここに移しました。変更の内容と寄稿者への参照は元のままです。

**バージョン 0.1.6（2026 年 11 月 18 日）。** この版で足したのは 2 つです。1 つは `yasakani bench --edit` です。速さの表の編集の課題 3 つを 1 つのコマンドで自分のパソコンで動かし、速さ、1 回の計算で進んだトークン数、答えが期待どおりかを表示します（[速さ](../README.ja.md#速さ)）。もう 1 つは GPU が複数のパソコンのための直しです（[#20](https://github.com/yasakani-dev/yasakani/issues/20)）。0.1.5 では GPU が 2 枚のパソコンで、ほかの GPU が見えていると `--device 1` が `graph instantiate failed` で止まることがありました。エンジンは開いたスレッドだけでなく呼ばれるたびに自分の GPU を選びます。`chat`・`serve`・`bench`・`selfcheck` はエンジンに `--device` の GPU だけを見せます（nvidia-smi が UUID を返さないときを除きます。[必要なもの](../README.ja.md#必要なもの)）。GPU が 1 枚なら、貪欲法で生成した文と速さは 0.1.5 と同じです（RTX 5090 で確認）。2 枚の GPU の PC ではまだ確かめていません。

**バージョン 0.1.5（2026 年 11 月 16 日）。** この版は直しの版で、多くは寄稿です。JSON 形のツール呼び出しで引数の値に `<function=...>` があっても正しく読みます。1 つの依頼に同じ画像が 2 回あってもエンコードは 1 回です。`--dll` や `YASAKANI_DLL` が無いファイルを指すと、ほかの DLL を読まずにエラーで止まります（[#12](https://github.com/yasakani-dev/yasakani/pull/12)）。ツール呼び出しで真偽値と宣言した引数は Python の書き方の `True`／`False` も、null を許す引数は `None` も値として読みます（[#21](https://github.com/yasakani-dev/yasakani/pull/21)）。エンジンはモデルファイルの見出しの長さを 64 bit で読みます（[#14](https://github.com/yasakani-dev/yasakani/pull/14)）。`YSKN_Q35_ATX_SPLITS` を 31 未満にしたときも短い文脈の全体を見ます（既定の 42 では変わりません。[#15](https://github.com/yasakani-dev/yasakani/pull/15)）。1 つのプロセスで 2 つのエンジンが同時に生成するときは先読みの状態を分けます（[#13](https://github.com/yasakani-dev/yasakani/pull/13)）。GPU のコードは 0.1.4 と同じなので、速度表は変わりません。`--max-ctx` を指定したとき、その長さと並べて入らなければ補助モデルの出口の表を読み込みません（[#17](https://github.com/yasakani-dev/yasakani/pull/17)）。GPU が複数のパソコンでは、`--device N` が `yasakani info` と nvidia-smi の GPU N になりました（[#20](https://github.com/yasakani-dev/yasakani/issues/20)）。同じ GPU にモニターをつなぐと生成が遅くなることがある、と FAQ に書きました（[#18](https://github.com/yasakani-dev/yasakani/issues/18)）。0.1.4 では編集が速くなり、長い入力を読み直すことが減りました。答えが入力を写すところでは、入力から写した続きを 1 回の計算で最大 64 トークンまとめて確かめます（これまで 16）。思考なしのコードと JSONL の編集は 0.1.2 の 1.67〜2.04 倍の速さになりました。思考なしのほかの課題は 0.96〜1.01 倍（同じ時に測った 0.1.3 の 0.99〜1.00 倍で、同じ速さ）で、答えは同じです（[速さ](../README.ja.md#速さ)）。起動ファイルはダウンロードの前に NVIDIA のドライバーの版を確かめ、`yasakani selfcheck` は RTX 5090 以外の GPU も確かめるようになりました（[必要なもの](../README.ja.md#必要なもの)）。同じ長い資料に続けて別の質問をするときも、資料を最初から読み直さなくなりました（資料が質問より前にあり、間にほかの依頼が無いとき。229,376 トークンの資料のあと、答え始めるまで 116 秒 → 0.37 秒。[長い文脈](../README.ja.md#長い文脈)）。サーバーは `tool_choice` の `required` と関数の指定も受け付けます（呼び出しは強制しません）。llama.cpp と同じ形の `timings` も返します。Linux ではソースからビルドした llama.cpp で画像も使えます（3 つとも [#8](https://github.com/yasakani-dev/yasakani/pull/8) の寄稿。Linux の画像は私たちは試していません）。[BUILDING.md](../BUILDING.md#linux-building-from-source) に Linux の節を作りました（[#10](https://github.com/yasakani-dev/yasakani/pull/10)・[#8](https://github.com/yasakani-dev/yasakani/pull/8)）。0.1.3 から、RTX 5090 以外の RTX 30・40・50 シリーズ（GPU のメモリ 16 GB 以上）でも動くように作りました。ただしこれらのカードではまだ動かしておらず、最適化もしていません（[必要なもの](../README.ja.md#必要なもの)）。0.1.3 では、まれに途中から別の文章になる問題の原因も直しました（[品質](../README.ja.md#品質)）。画像の入力は 0.1.2 から（任意。[#4](https://github.com/yasakani-dev/yasakani/pull/4) の寄稿）、ツール／関数呼び出し（`tools`）は 0.1.1 から対応しています。エンジン：[公開ページ](https://github.com/yasakani-dev/yasakani/releases/tag/v0.1.5)。モデル（Hugging Face）：[品質モデル](https://huggingface.co/yasakani-dev/Qwen3.8-27B-YASAKANI-quality)・[最速モデル](https://huggingface.co/yasakani-dev/Qwen3.8-27B-YASAKANI-speed)。
